
- [Create a page](https://developers.notion.com/reference/post-page) — current requests accept a parent `{page_id}` or `{data_source_id}`; database/data-source page properties must follow that source's schema.
- [2025-09-03 upgrade guide](https://developers.notion.com/guides/get-started/upgrade-guide-2025-09-03) — database IDs resolve through `GET /v1/databases/{database_id}`; use a returned `data_sources[*].id` as the new page parent. The current docs use the `2026-03-11` version header.
- [Retrieve a database](https://developers.notion.com/reference/retrieve-a-database) and [retrieve a data source](https://developers.notion.com/reference/retrieve-a-data-source) — database responses expose data sources, whose `properties` schema defines each table column. The connected target has one source with `Name` (title), `Date` (date), `Summary` (rich text), and `Review` (rich text).
- [Update data source properties](https://developers.notion.com/reference/update-data-source-properties) — add `Summary` as `{ "rich_text": {} }`; this preserves existing properties. The Notion integration must have update-content access.
- [List views](https://developers.notion.com/reference/list-views), [retrieve a view](https://developers.notion.com/reference/retrieve-a-view), and [update a view](https://developers.notion.com/reference/update-a-view) — a table view's `configuration.properties` array controls visible property order. Nuytelab preserves the connected database's current table-view settings and inserts `Summary` immediately after `Date`.

- [Working with views](https://developers.notion.com/guides/data-apis/working-with-views) and [list views](https://developers.notion.com/reference/list-views) — list base-database views with `GET /v1/views?database_id=...`, then retrieve each view's configuration. The view's table `configuration.properties` array is ordered; preserve the other table settings when updating it.
- [Retrieve a view](https://developers.notion.com/reference/retrieve-a-view) and [update a view](https://developers.notion.com/reference/update-a-view) — `GET /v1/views/{view_id}` supplies the current configuration; `PATCH /v1/views/{view_id}` accepts the table configuration and its ordered property array, allowing Summary to sit after Date without changing filters/sorts.
- [Notion table view help](https://www.notion.com/help/tables) — columns can also be reordered by drag-and-drop in the Notion UI. This is a fallback only; the integration API supports ordering via the view configuration.

No row/page data was created or backfilled during the schema update.
